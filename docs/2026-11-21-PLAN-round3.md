# Plan — N1: sensor noise as a simulator parameter (2026-11-21, round 3)

Status: **PLAN**, written before execution. Predecessor:
`2026-11-21-PLAN-round2.md`. Executed status appended at the bottom.

## Why

F3 established that the deterministic identity probe dies under **jitter**, not
under grid rounding (1.00 at every grid up to 20 units; 0.50 at 5 units of
jitter). The jitter currently lives inside the probe, which means every learned
arm would be measured on a synthetic perturbation invented by the scorer — not
on a world. A task you can hand to a model must be a *world* with a sensor
model, so the log itself has to carry the noise.

## N1 — `SimConfig.noise`, observable-only, deterministic

- `noise: float = 0.0` — uniform jitter of ±`noise/2` applied to the `pos` and
  `v` attributes of **observable** events only; oracle attributes stay exact, so
  the truth keeps being the truth.
- Seeded from `(seed, episode, "noise")` so an episode is reproducible byte for
  byte and does not depend on how many events preceded it elsewhere.
- `noise=0.0` must reproduce today's logs exactly (the default path is
  unchanged, which is what lets every existing corpus and gate stand).

## Gates

1. `noise=0` produces the same observable attributes as before (one canonical
   episode compared against a rebuilt one at 0.0).
2. Oracle attributes are identical at `noise=20` — the sensor cannot corrupt the
   answer key.
3. Two runs with the same seed produce identical noisy logs; a different seed
   produces different values.
4. The filter still enumerates worlds at `noise=2` on the parallel family (noise
   must degrade the score, not break the apparatus).
5. Measured curve: A2 top-1 on `parallel_recrossing_corpus(noise=q)` for
   `q ∈ {0, 2, 5, 10, 20}`, with the corpus size and any dropped episodes
   reported. Recorded as evidence for A3, still not a registered claim.

## Stop rule

Two FAILs on the same gate: record and stop. Do not tune noise until the number
looks interesting — the number is the result.

## Execution status — 2026-11-21 (appended after measurement)

- **N1 DONE.** `SimConfig.noise` jitters `pos`/`v` on **observable** events only,
  seeded from `(seed, episode, "noise")`; `noise=0.0` reproduces the previous
  logs exactly. Oracle attributes are byte-identical at `noise=20`, so the
  sensor cannot corrupt the answer key. 6 tests in `tests/test_noise.py`.
- **Gate 4 found a real apparatus limitation, not a test bug.** A 2-unit sensor
  on an otherwise exact world yields **zero** consistent worlds: continuity and
  contact are compared at `TOL = 1e-4`, so the filter collapses instead of
  degrading. The tolerance is now a stated parameter threaded through
  `_close` / `contact_ok` / `validate` / `_pairings` / `consistent_worlds` /
  `summarize`, default unchanged at `1e-4`, so every pre-existing corpus keeps
  its meaning. Encoded as
  `test_the_filter_breaks_at_default_tolerance_and_recovers_with_a_stated_one`
  (0 worlds at default, >0 at `tol=2.0`).
- **Measured curves** (`scripts/a3-degradation.py`), both on the parallel
  family, chance 0.25:

  | unit | probe jitter top-1 | world sensor noise top-1 |
  |---|---|---|
  | 0 / 0.01 | 1.00 | 1.00 |
  | 2 | 1.00 | 0.83 |
  | 5 | 0.50 | 0.33 |
  | 8 | 0.50 | — |
  | 10 | 0.50 | 0.33 |
  | 20 | 0.33 | 0.33 |

  Probe-level jitter is kinder than world-level sensing, which is what it
  should be. The world-level curve degrades and then **plateaus at 0.33, above
  the 0.25 floor**: the residual loses information but never loses to guessing.
- **RETRACTION (same day).** An earlier run of this measurement reported
  world-level top-1 = 0.17 at 20 units, i.e. below chance, and that was written
  here as "the first measured regime where a learned prior has something to
  add". It was an artifact: the noise RNG was seeded from
  `hash((seed, episode, "noise"))`, and Python randomises string hashing per
  process (`PYTHONHASHSEED`), so the same inputs scored 0.17 locally and 0.33 on
  CI. CI caught it. The seed is now int-only, `tests/test_noise.py` pins a
  golden attribute vector so cross-process drift fails loudly, and the
  below-chance claim is withdrawn: no measured regime shows the residual
  performing worse than chance.
- The corpus builder's "exactly four worlds" filter is a full-precision
  property: above `noise=0` it returns nothing, which initially hid the whole
  noisy regime. The measurement script builds noisy episodes directly and
  reports the world count instead (still 4.00 within the measured band).
