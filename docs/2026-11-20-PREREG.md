The distinctive contribution is none of the above. It is the combination:
**persistent, provenance-bearing world states → temporal/epistemic reasoning
→ falsifiable constraints on learned representations** — with the world store
auditable and revisable, which none of the cited works has.

## Claims (kept separate on purpose)

- **Claim A (v1, tested):** correct symbolic constraints preserve
  prediction-relevant distinctions under occlusion better than baseline JEPA
  and better than a structure-preserving shuffled-rule control.
- **Claim B (later, NOT tested by v1):** persistent, revisable EPEC/Physis
  reasoning feeds back and improves learning or world-state revision. v1 uses
  the event-calculus filter as validator/explainer only; it can demonstrate
  **auditable validation**, not improved learning. Do not report Claim B
  language from v1 results.

## Arms (GPU phase, three, matched)

1. **baseline** — JEPA alone (EB-JEPA video/action-conditioned example).
2. **EBC** — JEPA + energy-based constraints derived from the *observable*
   event log (enter/exit side, measured velocities, contacts).
3. **shuffled control** — JEPA + EBC computed from `controls.shuffle_rules`
   output: same rule count, same predicate vocabulary, same per-attribute
   marginals, same timestamps, same training budget; alignment destroyed,
   seed recorded.

## Data products and leakage rules (hard)

| Product | Contents | Allowed use |
|---|---|---|
| observable log | identity-free, camera-measurable events | JEPA/EBC inputs and training-time constraints |
| simulator ground truth | labelled trajectories incl. hidden contacts | evaluation and explicitly-labelled oracle experiments only |
| inferred log | possible worlds, hypotheses, provenance | predictions, EPEC validation, explanation |

Rules: oracle products never enter training. Actions are applied only to
visible balls, so no hidden action exists. Splits are by **independent
episodes and physical configurations** (config-family split), never
neighbouring frames.

## Task and recoverability

Emergence-side probe: given observable history, predict the ordered
entry→exit pairing. Recoverability: exit side and exit velocity are functions
of entry velocity and hidden contacts; hidden contacts leave a visible
pre-contact signature (approach geometry), so the task is
information-theoretically solvable, not trivially. Identity continuity is
meaningful because two balls are visually identical (association, not
tracking). The event-calculus filter enumerates the consistent worlds; the
JEPA arms are scored on whether their latents rank the *true* world higher
than the competing consistent world.

## Metrics (CPU-pre-registered; probes executed in GPU phase)

- M1 latent variation: Tr(Cov Z) and min_j Std(Z_j) (per SJEPA — effective
  rank reported too but never alone).
- M2 emergence-side discrimination: accuracy/calibration of the true pairing
  vs the competing consistent world, identical probe spec across all arms.
- M3 hidden-contact detection: AUC for "collision occurred", recoverable from
  observable pre-contact evidence.
- M4 world agreement: EPEC-consistent-world count per episode; rank of the
  oracle world among consistent worlds under each arm's latents.
- M5 auditability: violation counts of decoded continuations under the filter.

## Success and failure criteria (fixed now)

- Claim A is supported only if arm 2 beats arm 1 **and** arm 3 on both M2 and
  M3, with ≥3 independent seeds, means with sd reported, per config family.
- If arm 2 beats arm 1 but not arm 3: supervision confound — Claim A
  unsupported; that is the Phase 11D trap recurring and is reported as such.
- A negative result is a deliverable: file a receipt, do not tune until a
  positive appears. No metric is added after results exist; the probe spec is
  frozen before the first GPU run.

## v0.1 deviations from the original proposal

- Pure-python event-calculus filter; the clingo/ASP port (and probabilistic
  weighting, i.e. EPEC proper) is deferred to Claim B. The v0.1 filter is
  EPEC-*inspired*, unweighted, and is tested against known episodes.
- No diffusion, no GUI, no API surface beyond the library. Stochastic
  generation and any "imagined worlds" language wait for v2.
- epec-vanilla code is **not** vendored or copied (license unverified).
