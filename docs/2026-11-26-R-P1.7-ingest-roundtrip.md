# R-P1.7 ingest gate — met on 2026-11-26, closing the 2026-11-22 negative

The 2026-11-22 measurement (`2026-11-22-R-P1.7-ingest-measurement.md`) concluded
"no generic observation ingress exists", so `psychopomp.observation/1` could not
enter a Physis world and the gate was **not met**. That conclusion is correct for
the engine it measured (`physis` 1.8.7 on PATH) and **stale for the branch that
was written to fix it**.

## What changed

`feat/psychopomp-import` (`f015751f3c`, 6 commits, 858 lines, 5 files) adds
`physis import <schema> <file>` plus a store-level importer. It was pushed on
2026-11-24 and **never merged**: 245 commits behind `main`, and absent from the
installed binary. Merged here as `integrate/psychopomp-import-20261126`.

`physis import --help` on the merged build:

```
Usage: physis import [OPTIONS] <SCHEMA> <FILE>
  --path <PATH>   --dry-run   --json
```

## The gate, measured

Fixture: 24 R-P1.48 exit cells exported by the lane's own
`scripts/e1-roundtrip-export.py` (24 episodes, 24 rows, 24 subjects).

| step | command | result |
|---|---|---|
| import into an empty world | `physis import psychopomp.observation/1 fixture.jsonl` | `24 read, 24 appended, 0 duplicate` |
| re-import (idempotence) | same | `0 appended, 24 duplicate` |
| **round-trip query** | `physis subject episode:0:0` | **1 row**, typed props read back (`psychopomp_kind=exit_occ`, `psychopomp_provenance`, `psychopomp_schema`) |
| audit packet | `physis packet --out pkt --query …` | 24 observations, `sha256 aa29df00…` |
| verification | `physis packet-verify pkt` | `VERIFIED packet: 24 rows parse` |
| tamper one row, re-verify | append a junk line | `FAILED packet: hash mismatch`, **exit 1** |

The subject is `episode:0:0`, not `psychopomp:episode:0:0`: the importer writes
`source=psychopomp` and the unprefixed subject, so a query must use the subject
the world carries. Recorded because the first query I ran used the wrong form and
returned `0 row(s)` — which reads exactly like a broken importer and was not.

**A junk row is refused by hash, not by parse.** Appending `{"junk":true}`though
valid JSONchanges the digest, so `packet-verify` reports the mismatch rather than
accepting a well-formed lie.

## Two defects in the evidence, not in the importer

1. **The smoke script's conflict step could not fail.** It mutated
   `props.side = "right"`, which the first fixture row already was, so it
   re-imported an identical payload and reported `FAIL not refused`. Verified by
   hand that a genuine change *is* refused —
   `key psychopomp:episode:0:0#0 already holds different content; refused as a
   conflict, not overwritten`, exit 1 — and the mutation now flips the value and
   asserts it changed.
2. **My own tamper check read the wrong exit code.** `physis packet-verify … |
   tail -3; echo $?` reports `tail`'s status. The tool does `exit(1)` on a
   verification failure. Re-measured without the pipe: **exit 1**.

Both are the same failure mode as the tests in R-P1.63/64: an instrument that
cannot distinguish "the product refused" from "the test never asked".

## Consequence

- **R-P1.7's gate is met**: a psychopomp export round-trips into a Physis world,
  is queryable there with its provenance, and an audit packet over it verifies
  offline and fails on tampering.
- The dependency chain `R-P1.0 → … → R-P1.7` is now closed end to end, which is
  what the roadmap's stop rule wanted before integration work.
- The 2026-11-22 note is **not** retracted: it was true of 1.8.7. What was wrong
  was the roadmap still calling the gate unmet after the fix had been written and
  never merged.

## Still open

The importer accepts only the declared `psychopomp.observation/1` schema, so this
is not generic ingress: a second producer needs its own schema arm and its own
gate. Nothing here measures throughput at store scale, and the concurrency
evidence is the smoke script's two-process case (no duplicates, one process may
abort by design), not a stress test.
