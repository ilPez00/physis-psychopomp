## The store already had the lock; I was going to invent it

Read from `crates/physis-store/src/log.rs` at that revision:

- `append_observations_if(paths, items, condition)` — one cross-process lock
  around *load, condition, sequence assignment, append*. `condition(&existing)`
  runs **inside** it and `Ok(false)` aborts the whole batch.
- `observation_prefix` refuses a truncated tail:
  `"observation log has a torn tail; append refused without deleting evidence"`.
- `redact::scrub(&mut obs)` runs on every row immediately before the write.
- `Observation` carries `props: BTreeMap<String, String>` — typed facts beside
  the free-text body, which is a better home for our fields than JSON-in-body.
- Sequence exhaustion is checked (`checked_add`), not wrapped.

So the plan's "dedup under the store lock" was not a new mechanism: it is the
`_if` condition. What was missing is a *domain* key, and that is all this module
adds.

## What was implemented

`crates/physis-store/src/psychopomp.rs`, registered in `lib.rs`:

| rule | why |
|---|---|
| UTC `ingest_at` passed in by the caller; producer's `at` kept in `props["at_seconds"]` | reading simulated seconds as Unix time would date every row 1970 |
| only `evidence == "OBSERVED"` | a prediction is not a sighting |
| `provenance.source` starting `counterfactual:` refused | the producer never emits one; refusing beats relabelling |
| key `psychopomp:<subject>#<seq>` in `produced_by` | stable across runs, and visible to a reader |
| in-batch dedup before the store sees it; existing-log dedup by pre-filter; a **final condition inside the lock** aborts on a race | no duplicate row survives either path |
| `--dry-run` reads and validates, writes nothing | the caller decides when a world changes |
| torn tail refused | the store's own rule, not overridden here |

## What is still missing

  `Cmd` enum + dispatch and a CLI-level smoke test. That is the next unit.
- **Concurrency is argued, not measured.** The condition runs under the lock, but
  no test spawns two processes appending the same export. Until one does, "no
  duplicates under concurrent writers" is a code reading.
